## نتیجه: کدام بهتر است؟

| رتبه | موتور | برای محتوای آموزشی علمی |
|------|-------|--------------------------|
| 🥇 | **Manim** | بهترین. با «اشیاء ریاضی» کار می‌کنی (`Polygon`، `Line`، `MathTex`، `Create`، `Write`، `Transform`)، دستگاه مختصات آماده، و کلاس‌های آمادهٔ نمودار/معادله. برای ویدیوی درسی سریع‌ترین راه است. |
| 🥈 | **Remotion** | خیلی خوب. کنترل دقیق پیکسلی با SVG/React، فونت و رندر رسمی. اما همه‌چیز را خودت می‌چینی و برای انیمیشن هندسی باید مختصات را دستی حساب کنی. |
| 🥉 | **Motion Canvas / Revideo** | خوب. API برداری قوی (`Rect`، `Line`، `Txt`) و `createRef` برای تایم‌لاین. هزینهٔ راه‌اندازی بیشتر (بدون CLI در Motion Canvas، نیاز به تنظیم اندازه/نام صحنه در Revideo). |
| ۴ | **GSAP + SVG** | تایم‌لاین GSAP فوق‌العاده راحت است (`tl.to(..., 4.3)`) ولی خودِ گرافیک را باید SVG بنویسی. برای تایپوگرافی آموزشی خیلی خوب. |
| ۵ | **p5.js** | ساده و سرراست برای نقاشی روی canvas، اما تایم‌لاین دستی است و برای فریم‌به‌فریم باید همهٔ `progress`ها را خودت حساب کنی. |
| ۶ | **three.js** | برای این سناریوی دوبعدی overkill است؛ برای محتوای سه‌بعدی (مولکول، فیزیک، نجوم) گزینهٔ درست است. |
| ۷ | **Lottie** | **مناسب نیست.** Lottie قالب *پخش* خروجی After Effects است، نه ابزار نوشتن صحنه با کد. در محیط headless هم محدودیت دارد: رندرر SVG کار نکرد، کی‌فریم `scale` لایه رندر نشد و متن نیاز به overlay جداگانه داشت. |

## یادداشت‌های فنی هر موتور (در جریان همین سناریو)

- **Remotion**: بدون اصطکاک. فقط باید عرض/ارتفاع و تایمینگ‌ها را دستی مدیریت کنی.
- **Manim**: نمونهٔ ما از `Text` استفاده می‌کند نه `MathTex`، چون نصب LaTeX این محیط خراب است (در نصب استاندارد، `MathTex` بدون مشکل کار می‌کند و همین مزیت بزرگ Manim است).
- **Motion Canvas**: نام صحنه را خودِ پلاگین `?scene` تزریق می‌کند، پس نباید به `makeScene2D` نام داد (برخلاف Revideo). هم‌چنین `Polygon` در این محیط رندر نشد و مجبور شدم از `Rect` استفاده کنم.
- **Revideo**: نام صحنه باید صریح باشد، `outFile` فقط نام فایل باشد، و برای هم‌اندازه شدن با بقیه باید `settings.shared.size` را 1280×720 گذاشت (پیش‌فرض 1920×1080 است).
- **GSAP**: رسم خط «draw-on» با `strokeDashoffset` خیلی تمیز جواب می‌دهد؛ فقط `svgOrigin` برای بزرگ‌نمایی مربع‌ها لازم بود.
- **p5.js**: تابع سراسری `scale` با نام پارامتر تداخل می‌کند (یک بار به همین دلیل خطا خورد).
- **three.js**: برای نگاشت مستقیم مختصات پیکسلی باید دوربین orthographic را به شکل `(-W/2, W/2, H/2, -H/2, 0.1, 1000)` با `position.z = 10` بسازی؛ حالت `(0, W, 0, H, -10, 10)` هیچ‌چیز رندر نمی‌کند.
- **Lottie**: هندسه را با شکل‌های Lottie ساختیم ولی متن را با overlay؛ ضمناً رشد مربع‌ها با کی‌فریم اندازهٔ شکل انجام شد نه `scale` لایه.
